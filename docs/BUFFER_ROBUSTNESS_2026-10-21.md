# First upstream-DXVK P0 implementation: buffer robustness

## Bounded shader audit and decision

Ordinary DXVK still requires robustBufferAccess2; current Mavk truthfully does
not advertise it. Existing range metadata and integer buffer guards make this
a smaller implementation step than full clip/cull, multi-viewport or wireframe.
Image atomics remain explicitly rejected and deferred, rather than widening the
shader audit indefinitely. General update-after-bind is still deferred.

Wide loads may be checked as separate 32-bit accesses under robustness2, but
the specification does not make scalarization mandatory. Do not misclassify
whole-vector handling as a proven defect merely because it is not componentwise.
The implemented fix instead addresses a reproducible uninstrumented access.

## Proven defect and fix

The pinned bindless pass accepts an OpLoad/OpStore buffer pointer only when its
OpAccessChain base is a global OpVariable. Valid nested AccessChains therefore
passed compilation without byte-range guards. The new nested-buffer fixture
failed the pre-fix compiler test: private guard metadata was absent.

The shared compiler now runs SPIRV-Tools CombineAccessChains before bindless
instrumentation. This canonicalizes pointers, preserving the existing range
mechanism and metadata ABI. No new feature/extension bits, application-specific
conditions, shader storage writes, or runtime settings were introduced.

## Second concrete fix: generated byte-offset overflow

The pinned GenLastByteIdx computes stride*index, member offsets and last-byte
addition using32-bit IMul/IAdd. Index0x40000000 with stride4 wraps to0; adding
the last byte produces3, which incorrectly passes a four-byte descriptor bound.
Similarly,0x3fffffff*4 + memberOffset16 wraps during addition. This is a guard
arithmetic bug, not a reason to change application integer overflow semantics.

Shared SaturateGuardOffsets now follows ONLY generated expressions feeding
ULessThan checks against the generated four-index metadata reader. Multiplication
uses UMulExtended's high word; addition checks carry with low<left. Overflow
saturates the checked byte offset toUINT32_MAX, which fails the existing strict
less-than range comparison. Original application arithmetic, metadata traversal,
descriptor ABI and feature advertisements are unchanged. This is coupled to the
pinned instrumentation helper; do not change its naming/shape without regression.

## Third concrete fix / APK19: wide-index narrowing

Gen32BitCvtCode narrowed64-bit AccessChain indices before the byte-range test.
A value such as0x100000000 therefore became0 before the overflow fix could
recognize it. Shared saturation now handles generated UConvert/SConvert too:
preserve the source bit pattern, narrow, widen to the original unsigned width,
and reject lost bits through the same saturated-offset mechanism. Signed input
is bitcast at its original width, not illegally UConvert-ed to a signed type.
No shaderInt64 feature is added to a shader that did not already use it.

Actual Mali tests: unsigned64 high index and signed64 negative index readzero;
valid64 index0 reads0xA5A5A5A5, proving this is not a blanket rejection. All
three suppress an out-of-range write and preserve31 output/32 input words.
